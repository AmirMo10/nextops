# فناوری‌های پیشنهادی پروژه

[English](../en/TECH_STACK.md) · [فهرست](INDEX.md) · [نمودارهای معماری](DIAGRAMS.md) · [ارزیابی CPU](CPU_AI.md)

> **این راهنما پیشنهاد معماری و بخشی مستقر برای ارزیابی کنترل‌شده را پوشش می‌دهد.** Python 3.12، `uv`، Pydantic، FastAPI/Uvicorn، PostgreSQL از مسیر SQLAlchemy/Alembic/Psycopg، Ruff، mypy و pytest قفل شده‌اند. رابط فعلی از HTML/CSS/JavaScript محلی ساخته شده و هنوز جایگزین پیشنهادی React/Vite نیست. سرویس ثابت llama.cpp/Qwen روی CPU، اتصال، واحدهای systemd، Nginx/TLS، PostgreSQL برنامه و مسیر Zabbix با شاهد محدود مستقرند؛ کارایی و بازیابی تولیدی هنوز پذیرفته نشده است. [مانیفست انتشار](../status/current-release.yaml) را ببینید.

## ترکیب پیشنهادی برای شروع

برای رابط وب **React، TypeScript و Vite**، برای API **FastAPI و Pydantic** و برای داده **PostgreSQL، SQLAlchemy و Alembic** پیشنهاد می‌شوند. پردازشگر ماندگار با ظرفیت محدود، **درگاه MCP با مرز دسترسی مستقل** و یک سرویس محلی **llama.cpp روی CPU** این مجموعه را کامل می‌کنند.

برنامه را ماژولار بسازید؛ برای هر کتابخانه سرویس جدا ایجاد نکنید. API و پردازشگر می‌توانند کد دامنه را به اشتراک بگذارند، اما درگاه و اتصال‌دهنده‌ها برای حفاظت از اطلاعات ورود جدا می‌شوند. مرورگر فایل‌های ساخته‌شدهٔ رابط وب را از پراکسی معکوس می‌گیرد. این طرح به سرور برنامهٔ Node.js در محیط عملیاتی یا ارائه‌دهندهٔ خارجی هوش مصنوعی نیاز ندارد.

## ۱. فناوری‌های اصلی و مسئولیت هرکدام

جدول زیر هم بخش مستقر کنترل‌شده و هم انتخاب‌های آینده را نشان می‌دهد. هر مورد فقط زمانی مستقر است که مانیفست انتشار و وضعیت پروژه آن را ثبت کرده باشند. «اصلی» یعنی هدف پیاده‌سازی، نه پذیرش خودکار برای تولید. منابع پیوندشده قابلیت ابزار را توضیح می‌دهند؛ مناسب بودن عملی آن برای این سرور باید سنجیده شود.

|---|---|---|---|
| میزبان | Ubuntu 24.04 LTS به‌عنوان مبنا | محیط اولیه روی یک سرور | سیستم‌عامل موجود، پشتیبانی و تأیید مالک بررسی شود؛ سرور سالم را خودکار دوباره نصب نکنید. |

| سیستم رابط | Tailwind CSS و اجزای بازبینی‌شدهٔ shadcn/ui | توکن‌های مشترک، فرم، جدول، پنجره و اجزای سازگار با RTL [7] | کد اجزای واردشده بازبینی شود؛ صفحه‌کلید، کنتراست و کاربردپذیری فارسی همچنان آزمون می‌خواهند. |
| زبان | i18next و react-i18next | واژه‌نامه‌های محلی فارسی و انگلیسی [8] | ترجمه‌ها همراه برنامه باشند؛ سرویس ترجمهٔ میزبانی‌شده لازم نیست. |
| وضعیت API در رابط | TanStack Query | چرخهٔ دریافت داده، کش و تازه‌سازی [9] | کلید کش وابسته به محدوده باشد؛ در خروج یا تغییر دسترسی پاک شود؛ کش تأیید عملیات مرجع مجوز نیست. |
| ورودی و استقرار | Nginx و Docker Compose؛ مسیر جایگزین مستند با systemd | ورودی TLS و تعریف صریح فرایندها و شبکه‌ها [10] | یک حوزهٔ خرابی؛ پایگاه، مدل و MCP داخلی؛ بدون دسترسی برنامه به سوکت Docker. |
| نگهداری شواهد | فایل‌سیستم با دسترسی محدود و فراداده در PostgreSQL | هش محتوا، منبع و بازیابی مجاز | حذف اطلاعات محرمانه پیش از ارسال به مدل؛ نگهداری کنترل‌شده و بازیابی خارج از میزبان. |
| ابزار کیفیت | Ruff، mypy، pytest، HTTPX؛ Vitest و Playwright | قالب و نوع کد، قرارداد بک‌اند و آزمون مرورگر [11] | آزمون شبیه‌ساز، اعتبارسنجی تجهیز نیست؛ شکست، رد شدن و اجرا نشدن آزمون ثبت شود. |

Python و FastAPI، PostgreSQL، React و Vite، اجرای محلی CPU و MCP در مبنا انتخاب شده‌اند. پشتهٔ Python/FastAPI/PostgreSQL، پنل ایستای محلی، بسته‌بندی و استقرار بومی، پردازش CPU و مرز محدود Zabbix اکنون برای ارزیابی کنترل‌شده پیاده شده‌اند. React/Vite و SDK رسمی MCP همچنان کار آینده و نیازمند ارزیابی‌اند؛ پذیرش تولیدیِ بسته‌بندی و بازیابی باز است.

## ۲. فناوری رابط و الگوی تعامل

پیش از ساخت صفحه‌های متعدد، یک سیستم طراحی کوچک تعریف کنید. فاصله‌ها، تایپوگرافی، سطح‌ها، نشانگر تمرکز و وضعیت‌های سالم، هشدار، بحرانی، قدیمی، ردشده، در انتظار تأیید، شلوغ و نتیجهٔ نامشخص، توکن معنایی داشته باشند. رنگ تنها نشانهٔ وضعیت نباشد.

ترکیب پیشنهادی **Tailwind CSS، shadcn/ui و react-i18next** است. shadcn/ui راهنمای RTL دارد [7]، اما ترجمهٔ برچسب‌ها به‌تنهایی چیدمان را درست نمی‌کند. ناوبری، پنجره‌ها، منوها، جدول‌ها و حرکت تمرکز صفحه‌کلید در هر دو جهت آزموده شوند. نشانی IP، فرمان، مسیر فایل و شناسهٔ مدل در محدودهٔ چپ‌به‌راست نمایش داده شوند. تاریخ محلی برای نمایش است؛ زمان در ذخیره‌سازی UTC بماند.

TanStack Query وضعیت سمت سرور را مدیریت کند، نه اینکه موتور مجوز دوم شود. رویدادهای SSE از API احرازهویت‌شده نمای بررسی را تازه می‌کنند. برای وضعیت محلی رابط ابتدا از امکانات خود React استفاده کنید و کتابخانهٔ سراسری دیگری را بی‌نیاز اضافه نکنید. وضعیت خالی، در حال بارگذاری، دادهٔ قدیمی، نتیجهٔ ناقص، آفلاین و رد دسترسی آشکار باشد.

**پس از آماده شدن API توپولوژی و به‌صورت اختیاری:** React Flow برای نمایش تعاملی تجهیزات و وابستگی‌ها پیشنهاد می‌شود [12]. فقط گره‌های مجاز نمایش داده شوند؛ با زیرگراف محدود به رخداد، بوم فقط‌خواندنی و نمای جدولی قابل‌استفاده با صفحه‌کلید شروع کنید. این ابزار نمایشگر رابط است، نه پایگاه توپولوژی. لازم نیست همهٔ تجهیزات دائماً در یک گراف متحرک نمایش داده شوند.

تمام فایل‌های رابط باید هنگام اجرا محلی ارائه شوند. مجوز و توزیع فونت جداگانه بررسی می‌شود. این پیشنهاد به فونت CDN، آیکون میزبانی‌شده، تحلیل رفتار خارجی یا درخواست ترجمهٔ بیرونی نیاز ندارد.

## ۳. الگوی هوش مصنوعی مبتنی بر CPU

| نوع کار | نقطهٔ شروع | شرط انتخاب یا ارتقا |
|---|---|---|
| تجزیهٔ داده، مجوز، زمان‌بندی و دستورالعمل‌ها | کد قطعی و نوع‌دار Python | آزمون واحد، سیاست و سناریوهای سوءاستفاده |
| تولید اصلی پاسخ | یک مدل چندزبانهٔ کم‌دقت‌شده در حدود ۷ تا ۹ میلیارد پارامتر با llama.cpp محلی | کیفیت فارسی و انگلیسی، صحت پارامتر ابزار، زمان اولین توکن، تأخیر کامل و حافظه |
| دسته‌بندی سبک | مقایسهٔ مدل محلی کوچک‌تر با طبقه‌بندی قطعی | بهبود قابل‌اندازه‌گیری نسبت به راه ساده‌تر |
| تحلیل با کیفیت بالاتر | بررسی نامزد حدود ۱۴ میلیارد پارامتری پس از ثبت مبنا | بهبود کیفیت، تأخیر سنجیده‌شده را توجیه کند؛ داشتن RAM کافی دلیل انتخاب نیست. |
| بردارسازی برای بازیابی | یک مدل چندزبانهٔ CPU پس از نیاز واقعی قابلیت بازیابی | بازیابی فارسی، بارگذاری آفلاین، ابعاد و نسخهٔ بردار و هزینهٔ CPU |
| بازرتبه‌بندی | در شروع غیرفعال | بهبود اثبات‌شدهٔ بازیابی در بودجهٔ مشترک منابع |

نمونه‌های `Qwen3-8B` و `Qwen3-Embedding-0.6B` همچنان **نامزدهای ارزیابیِ ذکرشده در مشخصات** هستند؛ این متن آن‌ها را جدیدترین یا بهترین مدل معرفی نمی‌کند. مجوز، بازبینی، روش کاهش دقت، توکن‌ساز، قالب گفت‌وگو و checksum مدل جداگانه بررسی می‌شوند.

با یک سرویس تولید پاسخ و یک درخواست فعال شروع کنید. انتظار صف، پردازش ورودی، تولید پاسخ، صدک‌های ۵۰ و ۹۵ زمان کامل، لغو و فشار منابع در بار ترکیبی سنجیده شوند. سقف CPU و رشته‌ها سراسری باشد؛ یک مخزن ۹۰رشته‌ای را در چند پردازشگر تکثیر نکنید. اعلام شلوغی و به تعویق انداختن کار دسته‌ای، از صف نامحدود بهتر است. جزئیات در [هوش مصنوعی روی CPU](CPU_AI.md) آمده است.

| جزء اختیاری | زمان اضافه شدن | دلیل فعال نبودن در شروع |
|---|---|---|

| SDK و Collector مربوط به OpenTelemetry | ردیابی بین فرایندها به پرسش عملیاتی مشخصی پاسخ دهد [14] | فقط دادهٔ لازم جمع‌آوری شود؛ اطلاعات محرمانه حذف و خروجی محلی بماند. |
| Redis | اندازه‌گیری نیاز مستقل کش یا محدودسازی نرخ را نشان دهد | کار و تأیید از قبل مرجع PostgreSQL دارند؛ Redis مرجع دوم نشود. |
| React Flow | قابلیت توپولوژی بازبینی‌شده و API گراف محدود وجود داشته باشد | پیش از مفید شدن مدل شواهد، وابستگی نمایشی اضافه نشود. |
| رابط مدیر اطلاعات محرمانه | سرویس داخلی و تأییدشده برای نگهداری رمزها وجود داشته باشد | نسخهٔ اولیه هم حفاظت رمز و بازیابی کلید می‌خواهد؛ فایل `.env` ساده جایگزین عملیاتی نیست. |

اختیاری بودن این ابزارها به معنای اختیاری بودن امنیت نیست. احراز هویت، کنترل دامنهٔ دسترسی، ممیزی، بررسی مقصد مجاز، اعتبارسنجی TLS و SSH و رد پیش‌فرض، جزو پایه‌های پروژه‌اند.

## ۶. نسخه‌بندی، بسته‌بندی و ترتیب استفاده

پس از تأیید مرحلهٔ صفر، نسخه‌های پشتیبانی‌شده و سازگار انتخاب شوند؛ برچسب `latest` یک دستور نصب مبنای انتشار نباشد. فایل قفل بک‌اند و یک فایل قفل فرانت‌اند ثبت شوند و نسخهٔ Node و Python، commit و گزینه‌های ساخت محیط CPU، digest تصویرها و مشخصات مدل‌ها مشخص باشند. `uv` از قفل و همگام‌سازی پشتیبانی می‌کند [1]؛ اما نیاز به آماده‌سازی بسته‌های آفلاین را حذف نمی‌کند.

ابتدا قرارداد نوع‌دار دامنه و سیاست و آزمون‌های رد درخواست ساخته شوند. سپس مهاجرت PostgreSQL، وضعیت ماندگار و ممیزی اضافه شوند و بعد سنجش CPU محلی و مسیر فقط‌خواندنی Linux و Zabbix تکمیل شود. اجزای رابط بر اساس API بازبینی‌شده ساخته شوند؛ بازیابی، توپولوژی و ابزارهای اختیاری پایش هنگام نیاز اضافه شوند. ترتیب کامل در [نقشهٔ راه](ROADMAP.md) حفظ شده است.

فایل‌های انتشار باید فهرست وابستگی، مجوز و checksum داشته باشند. مدل، wheel یا تصویر، فایل رابط، فایل‌های مستندات API محلی و مرورگرهای آزمون در آماده‌سازی کنترل‌شده تهیه شوند. کمبود فایل در اجرا باید خطای روشن بررسی اولیه بدهد، نه دانلود پنهانی. ابزار توسعه لزوماً وابستگی محیط عملیاتی نیست.
