# توسعه، گردش‌کار GitHub و انتشار

[English](../en/DEVELOPMENT.md) · [فهرست](INDEX.md)

**وضعیت: قواعد توسعه. در این مرحله CI برنامه و استقرار خودکار تنظیم نشده‌اند.** مبنا: بخش‌های ۴، ۷، ۸ و ۲۱ تا ۲۶ مشخصات اصلی.

## پیش از پیاده‌سازی بررسی کنید

[AGENTS.md](../../AGENTS.md)، مشخصات اصلی، وضعیت پروژه و کار بعدی خوانده شوند. وضعیت Git، دستورهای پروژه، فایل‌های ثبت‌شده، manifest، فایل قفل، آزمون، migration و تنظیمات استقرار بررسی شوند. تغییرات ثبت‌نشده و پیاده‌سازی موجود حفظ شوند. اسکریپت پیش از اجرا بازبینی و در محیط جدا و بدون اطلاعات ورود عملیاتی آزمایش شود. reset یا clean مخرب، بازنویسی کار دیگران و تغییر تاریخچه مجاز نیست.

کار برنامه با برش آزمودهٔ قرارداد دارای نوع و سیاست قطعی 1A شروع شده است. هنوز API، UI، پایگاه، connector یا سرویس AI قابل‌اجرا وجود ندارد؛ قبولی unit این برش، قبولی برنامهٔ مستقر نیست. معماری مرحلهٔ صفر در ۲۱ سپتامبر ۲۰۲۶ پذیرفته شد، اما شناخت سخت‌افزار و همهٔ مجوزهای زیرساخت شرط‌های جدا باقی می‌مانند.

برای برش Python فعلی، محیط قفل‌شده با `uv sync --extra dev --frozen` نصب و سپس `uv run --extra dev ruff check packages tests`، `uv run --extra dev mypy packages tests` و `uv run --extra dev pytest` اجرا شود. `uv.lock` فقط همراه تغییر وابستگیِ بازبینی‌شده دوباره تولید و پیش از کار انتشار `uv audit --frozen` اجرا شود.

## نظم ماژول‌ها

قواعد دامنه از ورودی‌وخروجی چارچوب مستقل باشند. کاربردها به رابط‌ها وابسته‌اند و لایهٔ زیرساخت آن‌ها را پیاده می‌کند. قرارداد میان API، گردش‌کار، سیاست، درگاه و اتصال‌دهنده دارای نوع باشد. Python باید type hint، توضیح روشن API و مدیریت خطا داشته باشد. از منطق تکراری و فایل بسیار بزرگ عامل یا ابزار عمومی پرهیز شود. شناسه‌های کد انگلیسی می‌مانند؛ متن محصول و مستندات کاربر فارسی و انگلیسی دارند.

پوشهٔ کد، manifest و lock زمانی ساخته شوند که پیاده‌سازی واقعی آغاز می‌شود، نه به‌صورت جای‌خالی گمراه‌کننده. رفتار پشتیبانی‌نشده باید خطای صریح بدهد؛ پاسخ شبیه‌سازی‌شده نباید در مسیر عملیاتی موفقیت واقعی جلوه کند.

## تحویل قابل‌بازبینی در GitHub

شاخهٔ کوتاه‌عمر، commit کوچک، معیار پذیرش روشن و pull request به‌کار رود. هر ویژگی به نیاز اولیه و مرحلهٔ مربوط متصل شود. هر تحویل باید راهنمای هر دو زبان، وضعیت، کار بعدی و ردیابی را به‌روز کند. CODEOWNERS و قالب‌ها به بازبینی کمک می‌کنند، اما فعال بودن حفاظت شاخه را ثابت نمی‌کنند. قواعد main و بازبینی باید جداگانه تنظیم و بررسی شوند.

CI آینده شامل قالب‌بندی، lint، بررسی نوع، آزمون واحد و قرارداد و امنیت، PostgreSQL واقعی، ساخت رابط و آزمون مرورگر، کشف رمز، بررسی وابستگی و manifest انتشار است. action بازبینی‌شده با SHA ثابت و مجوز حداقلی اجرا شود. این‌ها نیازهای آینده‌اند، نه ادعای وجود خط لولهٔ سبز.

کد PR غیرقابل‌اعتماد در worker موقت و جدا، بدون رمز عملیاتی و مسیر شبکهٔ مدیریت اجرا شود. runner دائمی و دارای اختیار روی G10 در اختیار PR دلخواه قرار نگیرد. checkout غیرقابل‌اعتماد با `pull_request_target` و secrets اجرا نشود. آزمون سخت‌افزار معتبر به مسیر جدا، مجوز و محدودیت منابع نیاز دارد.

## انتشار و استقرار

نسخهٔ تأییدشده tag شود و هویت برنامه، وابستگی، کانتینر و مدل، هش و فهرست اجزای نرم‌افزار و مدل ثبت شوند. مالک نسخهٔ تأییدشده را صریحاً برای استقرار انتخاب می‌کند؛ هر push نباید محیط عملیاتی را تغییر دهد. سرور می‌تواند فایل مجاز را از مسیر خروجی دریافت کند و نیازی به SSH عمومی نیست.

پیش از استقرار، هویت فایل، سازگاری تنظیمات، پشتیبان، ترتیب migration و منابع و درگاه‌ها بررسی شوند. پس از آن، سلامت و رفتار مورد انتظار آزموده شود. بازگرداندن برنامه تغییر schema را برنمی‌گرداند؛ سازگاری داده یا مسیر restore آزموده لازم است. بستهٔ آفلاین محصول انتشار صریح است، نه دانلود زمان اجرا.

## هماهنگی عامل‌ها و تعریف پایان کار

کار موازی فقط برای وظیفهٔ مستقل و محدود مناسب است. معمار اصلی مالک قراردادهاست؛ بازبین امنیت مرز اجرا و اطلاعات ورود و تأیید را بررسی می‌کند؛ بازبین CPU/SRE منابع و عملیات را می‌سنجد؛ بازبین محصول و رابط، فارسی طبیعی و جریان کامل کاربر را بررسی می‌کند. در صورت نیاز شاخه یا worktree جدا استفاده شود. چند عامل هم‌زمان migration، قرارداد مشترک یا lock را بازنویسی نکنند. اجرای عامل موازیِ رخ‌نداده ادعا نشود.

کار زمانی تمام است که کد واقعی، آزمون مرزی، فرمان و نتیجهٔ ثبت‌شده، بازبینی امنیت، راهنمای دوزبانه، ردیابی و commit معنادار داشته باشد. mock آزمون تجهیز واقعی نیست. آزمون شکست‌خورده باید اصلاح یا صادقانه گزارش شود، نه برای سبز شدن تضعیف شود.
