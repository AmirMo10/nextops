# قراردادهای پیکربندی

[English](../en/CONFIGURATION.md) · [فهرست](INDEX.md)

**وضعیت: بخشی از پیکربندی runtime پیاده شده و قرارداد کامل فایل‌محور هنوز پیشنهادی است.** loader دارای نوع و fail-closed برای مرز برنامه/پایگاه/session و مرز سرویس محلی llama.cpp وجود دارد. نام فایل‌های زیر از مشخصات اصلی آمده‌اند و مقدار نمونه، فایل اجرایی فعلی نیست.

## تفکیک تنظیمات

| فایل پیش‌بینی‌شده | مسئولیت |
|---|---|
| `app.example.yaml` | محیط، زبان، مسیر داده، هویت سرویس، مقصدهای محلی و محدودیت‌ها |
| `models.example.yaml` | مسیر و نسخه و هش مدل، قابلیت، قالب و بودجهٔ CPU |
| `inventory.example.yaml` | شناسهٔ ثابت تجهیز، نوع، محیط، مقصد مجاز، برچسب و ارجاع به اطلاعات ورود |
| `credentials.example.yaml` | فقط شناسهٔ ورودی خزانه؛ بدون رمز یا کلید رمزگشایی |
| `policies.example.yaml` | اصل رد پیش‌فرض، عملیات نام‌دار، ریسک، تأیید و سقف اجرا |
| `resource-profiles.example.yaml` | تخصیص سنجیدهٔ CPU و RAM، رشته، هم‌زمانی و صف |

پیاده‌سازی فایل‌محور باقی‌مانده باید schema دارای نوع، پیام خطای روشن، نسخه‌بندی تنظیمات و ترتیب بارگذاری مستند داشته باشد. متغیرهای محیطی فعلی را `AppSettings` و `LlamaCppSettings` تعریف می‌کنند؛ متغیر پشتیبانی‌نشده در دستور نصب ابداع نشود. وضعیت برنامه در PostgreSQL نگهداری می‌شود؛ YAML قابل‌تغییر جای صف کار را نمی‌گیرد.

## زبان و هویت تجهیز

فارسی و انگلیسی پشتیبانی شوند و طبق نیاز اولیه، فارسی زبان پیش‌فرض باشد. مقدار معنایی داده از برچسب ترجمه‌شده جدا بماند. زمان داخلی UTC و نمایش محلی قابل‌تنظیم باشد. شناسهٔ تجهیز، نام interface، فرمان و فیلد پروتکل ترجمه نشوند. متن اصلی تشخیص حفظ شود؛ حذف اطلاعات محرمانه استثنایی صریح و علامت‌گذاری‌شده است.

هر تجهیز به شناسهٔ ثابت، دامنهٔ سازمان و محیط، نوع، مالک و برچسب، نشانی مجاز، قابلیت و نسخهٔ مشاهده‌شده، زمان آخرین بررسی و ارجاع به اطلاعات ورود نیاز دارد. در صورت ابهام نام، سامانه نباید بی‌صدا یکی از تجهیزات را انتخاب کند. تغییر مؤثر موجودی، فرض‌های تأیید قبلی را باطل می‌کند.

## فهرست مدل‌ها

ارائه‌دهندهٔ مدل فقط به سرویس یا فایل محلی CPU اشاره می‌کند. قابلیت تولید، بردارسازی و بازرتبه‌بندی جدا ثبت می‌شوند؛ صرف وجود تنظیمات به معنای سلامت نیست. نبود فایل، ناهماهنگی هش، قالب نامعتبر یا ابعاد ناسازگار باید خطای روشن بدهد. تغییر مدل بردارسازی یا ابعاد آن نیازمند تغییر سازگار نمایه است؛ بردارهای ناسازگار نباید مخلوط شوند.

بودجهٔ رشته از تعداد CPU نصب‌شده حدس زده نشود. پروفایل منابع تا پیش از اندازه‌گیری روی میزبان واقعی تأییدنشده است. مدل، بردارسازی، کارها، API و پایگاه داده باید یک بودجهٔ مشترک داشته باشند. محیط‌های توسعه، آزمایشی و عملیاتی هویت، موجودی و مخزن دادهٔ جدا دارند.

## اطلاعات محرمانه و مسیر داده

تنظیمات عملیاتی بیرون از checkout و با مالکیت محدود قرار گیرند. مسیرهای پیشنهادی و قابل‌تغییر `/etc/nextops`، `/var/lib/nextops` و `/srv/nextops/models` هستند. mount و فضای آزاد پیش از استفاده بررسی شود. `.env` فقط برای توسعهٔ محلی محدود مناسب است و خزانهٔ عملیاتی نیست. کلید بازیابی رمزگشایی کنار اطلاعات ورود رمز‌شده نگهداری نشود.

نمونهٔ مخزن می‌تواند نام تجهیز ساختگی و شناسهٔ ارجاع داشته باشد؛ نباید حساب قابل‌استفاده، token، فهرست نشانی خصوصی یا نام میزبان عملیاتی داشته باشد. وزن مدل، لاگ، dump و آرشیو پشتیبان در Git قرار نگیرند.

## کنترل تغییر

تغییر مدل و سیاست باید نسخه‌دار، قابل‌ممیزی، اعتبارسنجی‌شده و دارای برنامهٔ بازگشت باشد. درست پیش از اجرا، مجوز و وضعیت اولیه دوباره بررسی شوند. خروجی مدل حق تغییر سیاستِ مجازکنندهٔ خودش را ندارد. تنظیمات باید پردازش خارجی را رد کنند و تا مرحلهٔ مستقل و تأییدشدهٔ اقدام اصلاحی، همهٔ تغییرات زیرساخت را غیرفعال نگه دارند.
