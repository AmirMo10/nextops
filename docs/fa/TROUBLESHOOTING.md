# عیب‌یابی بدون میان‌بُر ناایمن

[English](../en/TROUBLESHOOTING.md) · [فهرست](INDEX.md)

**وضعیت: نیازهای دستورالعمل عیب‌یابی؛ نه شاهد وجود سرویس نصب‌شده.** مبنا: بخش‌های ۱۰ تا ۱۴ و ۱۸ تا ۲۱ مشخصات اصلی. پیش از تغییر، زمان، شناسهٔ اجرا و عملیات و خطای پالایش‌شده ثبت شوند.

| نشانه | بررسی ایمن | اقدام نامجاز |
|---|---|---|
| پس از clone برنامه اجرا نمی‌شود | وضعیت پروژه و محیط توسعه را بررسی کنید؛ factory منبع ASGI و migration وجود دارد، اما installer و unit تولید نداریم و تنظیمات بدون secret و URL پایگاه لازم عمداً fail-closed است | ابداع installer تولید، استفاده از secret نمونه یا گزارش خرابی سرویس مستقرنشده |
| پاسخ مدل کند است | زمان صف، ورودی و تولید را جدا کنید؛ سهم CPU، NUMA، رشته، زمینه و بار مشترک را بسنجید | افزایش همهٔ workerها به ۹۰ رشته یا انتخاب مدل بزرگ‌تر فقط به‌دلیل RAM آزاد |
| مدل در دسترس نیست | مسیر و هش فایل محلی، ساخت CPU، قالب و سازگاری مدل و سقف منابع بررسی شود | انتقال به API خارجی یا دانلود در زمان اجرای آفلاین |
| دسترسی رد می‌شود | هویت، دامنهٔ تجهیز و محیط، ابزار نام‌دار و سیاست فعلی بررسی شود؛ تغییر توسط مدیر مجاز انجام شود | حذف کنترل دسترسی یا دادن رمز مدیر به مدل |
| تأیید پذیرفته نمی‌شود | هش دقیق، انقضا، شناسهٔ یک‌بارمصرف، وضعیت اولیه و مجوز فعلی دو طرف بررسی شود | استفاده از تأیید قدیمی پس از تغییر آرگومان یا مقصد |
| اتصال timeout می‌شود | مسیر مجاز، هویت TLS یا SSH، اطلاعات ورود محدود، نسخه و API و مهلت خروجی بررسی شود | خاموش کردن بررسی گواهی، پویش شبکهٔ نامرتبط یا تکرار کورکورانهٔ تغییر |
| عیب‌یابی SQL شکست می‌خورد | موتور و نسخه، مجوز view تشخیصی، query محدود و حساب فقط‌خواندنی بررسی شود | اعطای دسترسی کامل مدیر پایگاه |
| چیدمان فارسی خراب است | RTL، جداسازی شناسهٔ LTR، فونت محلی و آزمون مرورگر هر دو زبان بررسی شود | ترجمهٔ فرمان اجرایی یا تغییر شناسهٔ تجهیز |
| تحلیل علت قدیمی یا گمراه‌کننده است | تازگی منبع، بازهٔ زمان، اختلاف ساعت، دامنه، شاهد ناقص و علت جایگزین بررسی شود | معرفی هم‌بستگی یا خاطرهٔ رخداد قدیمی به‌عنوان علت فعلیِ تأییدشده |
| ممیزی یا پایگاه قطع است | آمادگی کاهش‌یافته اعلام و تغییر متوقف شود؛ ذخیره‌سازی ماندگار بازیابی شود | ادامهٔ تغییر بدون ممیزی یا ادعای ثبت کار انجام‌نشده |
| فشار دیسک یا حافظه وجود دارد | بودجه، نگهداری داده و پاک‌سازی یا پشتیبانِ مجاز بررسی شود | حذف دادهٔ ناشناخته، آزمون دیسک مخرب یا پاک کردن cache میزبان مشترک |
| نتیجهٔ تغییر نامشخص است | `OUTCOME_UNKNOWN` ثبت، وضعیت تازه جمع و در صورت نیاز دستی بررسی شود | علامت موفقیت بر اساس timeout یا اجرای دوبارهٔ بی‌بررسی |

## اطلاعات لازم برای پیگیری

نسخه و commit، نسخهٔ جزء و مدل، ارجاع تنظیمات پالایش‌شده، شناسهٔ اجرا و عملیات و پیگیری، بازهٔ زمانی، انتظار در برابر مشاهده، دامنه و روش بازتولید ثبت شوند. شواهد امن نگه داشته شوند. نشانی عملیاتی، رمز و خروجی خام شناسایی در issue عمومی قرار نگیرند.

## اصل بازیابی

راه‌اندازی مجدد فرایند ثابت نمی‌کند اقدام راه دور متوقف شده است. سلامت endpoint ثابت نمی‌کند اتصال به نسخهٔ خاص فروشنده کار می‌کند. بازگشت کانتینر نیز سازگاری migration یا تأییدها را تضمین نمی‌کند. پس‌شرط مرتبط بررسی و موارد حل‌نشده صریح نگه داشته شوند.

تغییر میزبان یا شبکه به مجوز و راه بازیابی دسترسیِ آزموده نیاز دارد. درخواست مستندسازی به‌خودی‌خود اجازهٔ تغییر سرور نیست.
