## Executive position

NextOps has reached a controlled user-testing checkpoint. The first complete read-only path is live
across the four Ubuntu 24.04 servers: a user signs in through the private TLS application panel,
requests an investigation in English or Persian, receives current evidence from Zabbix through the
restricted connector, and obtains an explanation generated by the local CPU-only model.

The deployed slice is suitable for supervised user testing, not production acceptance. It covers
one approved self-monitoring host and a bounded summary operation. Durable investigation audit,
offline-WAN acceptance, backup and restore drills, failure exercises, and broader monitored-host
coverage remain open.

## Delivered user-testing capability

- A private HTTPS panel with English left-to-right and Persian right-to-left interfaces.
- Protected local sign-in; no infrastructure credential is exposed to the browser or model.
- A fixed, read-only investigation workflow rather than arbitrary JSON-RPC, URL, command or write
  access.
- Current Zabbix evidence with source version, host, collection time, metric observation time,
  stale-data state and active-problem count.
- A local CPU-generated explanation grounded in the returned evidence, with no cloud inference
  fallback.
- Native systemd deployment with immutable release directories, stable links, root-owned protected
  configuration and credentials, loopback backends, private TLS and host firewalls.
- Separate restricted SSH tunnels from the application server to the AI and connector services.

## Acceptance evidence

- Repository checks passed: Ruff formatting and lint, strict mypy across 57 files, documentation and

  skipped on the desktop because no local database URL was supplied.
- Connector verification returned Zabbix 7.0.30, one approved host, eight current metrics, zero
  active problems and zero stale metrics.
- Authenticated end-to-end checks passed for live monitoring and grounded generation in both
  languages. The English and Persian requests each returned the configured 128-token response.
- Browser QA verified the English sign-in presentation and the genuine Persian RTL layout. The full
  authenticated flow was also exercised programmatically against the deployed HTTPS endpoint.
- All four servers reported healthy systemd state, no failed units, no pending package update and no
  required reboot at the deployment checkpoint.

## Security posture

The current slice deliberately limits authority. Zabbix credentials exist only on the connector;
the connector API is loopback-only; its API role permits `host.get`, `item.get` and `problem.get`
for one approved host group; and a non-allowlisted method was verified as denied. The model receives
normalized evidence, not infrastructure credentials, and has no change or approval capability.
Only SSH and the intended private HTTPS endpoint are allowed by the relevant host firewalls.

## Remaining work before production acceptance

1. Persist each investigation, evidence reference, model result and security decision in the durable
   run and append-restricted audit stores.
2. Add approved production hosts, templates and service-level evidence without broadening the
   connector beyond explicitly reviewed read operations.
3. Complete Stage 1E with WAN blocked: cold starts, fresh login, dependency failures, revoked tokens,
   stale data, low-space handling, resource limits and a fresh-client test.
4. Establish and exercise independent PostgreSQL, Zabbix, configuration and release backup/restore
   procedures, then prove rollback for every deployed role.
5. Add operational dashboards, alerting, log retention, certificate/key rotation and a documented
   user-test feedback and defect workflow.

## Presentation conclusion

NextOps now has a functioning, security-bounded product slice rather than only prepared
infrastructure. It is ready for supervised user testing of the bilingual, read-only investigation
experience. Production readiness must wait for durable audit, broader approved monitoring scope,
offline and failure acceptance, and demonstrated backup, restore and rollback.
